# Shopify — الفرونت إند (React + Vite)

فرونت إند كامل لمشروع الباك إند اللي رفعته (Chater)، مبني بـ React و Vite، ومتصل بكل نقاط الـ API الموجودة عندك (تسجيل/دخول بخطوتين، الأدوات، التعليقات والتقييمات، وطلبات الحجز/الدفع، ولوحة تحكم للمديرين والأدمن).

## التشغيل

```bash
cd frontend
npm install
cp .env.example .env   # وعدّل VITE_API_URL لو السيرفر شغال على بورت مختلف
npm run dev
```

هيفتح على `http://localhost:5173`، وهو بيتوقع إن الباك إند شغال على `http://localhost:3000` (تقدر تغيّرها من `.env`).

## هيكل المشروع

- `src/api` — الاتصال بالسيرفر (axios) وكل الـ endpoints مجمّعة حسب المورد (users/items/comments/payments).
- `src/context/AuthContext.jsx` — إدارة تسجيل الدخول والتوكن والمستخدم الحالي.
- `src/components` — عناصر مشتركة (نافبار، بطاقة منتج، تقييم بالنجوم، حراسة المسارات...).
- `src/pages` — كل صفحة (المتجر، تفاصيل الأداة، الحجز، صفحات الحساب) + `pages/admin` للوحة التحكم.

## ملاحظات مهمة عن الباك إند ⚠️

وأنا بابني الفرونت لاحظت شوية حاجات في الباك إند نفسه محتاجة تتصلّح عشان الموقع يشتغل صح، مش حاجة أقدر أعالجها من الفرونت لوحده:

1. **السيرفر مش هيشتغل أصلاً حاليًا**: `app.js` بيستخدم `fs.existsSync` و `fs.mkdirSync` من غير ما يعمل `require("fs")` فوق. لازم تضيف `const fs = require("fs");` في أول الملف.
2. **رفع صور الأداة (`POST /items/create` و `PUT /items/:id/edit`)**: الترتيب في `items.router.js` غلط — الـ `itemValidator` (فاليديشن) شغال *قبل* `imageUpload` (multer)، فلما الطلب بيبقى `multipart/form-data` الفاليديشن بيشتغل قبل ما الحقول النصية تتقرأ أصلاً، فهيفشل دايمًا. الحل: حط `imageUpload` قبل `itemValidator` في الراوتر.
3. **`itemValidator` بيتحقق من حقول مش موجودة فعليًا**: بيدوّر على `size` و `image` بينما الكنترولر والـ schema بيستخدموا `min` و `max` و `images` (مصفوفة). لازم تتظبط الفاليديشن عشان تتوافق مع الكنترولر.
4. **`GET /items` مش بيرجّع `_id` للأداة**: في `getAllItems` بترجع بس name/images/price/category/min/max من غير `id`، فمفيش طريقة إن المستخدم يضغط على المنتج ويشوف تفاصيله من صفحة القائمة. أضفت fallback في الفرونت لكن لازم تضيف `id: item._id` في الـ response.
5. **راوتات الكومنتات فيها تعارض أسماء بارامترز**: الراوتر بيستخدم `:id` (زي `/comments/item/:id`, `/comments/edit/:id`, `/comments/delete/:id`) لكن الكنترولر بيقرا `req.params.itemid` / `req.params.commentid`. لازم تتوحّد التسمية. وكمان راوت إنشاء الكومنت `POST /comments/create` مفيهوش `itemId` في الرابط أصلاً مع إن الكنترولر محتاجه.
6. **حذف طلب حجز (`deletePay`) بيدور على `username` بتاع الشخص اللي عامل لوجين (المدير/الأدمن) مش صاحب الطلب الأصلي**، فلو مدير حاول يحذف طلب حجز خاص بمستخدم تاني هيفشل. لو عايز الأدمن/المدير يقدروا يحذفوا أي طلب، شيل شرط الـ `username` من `Pay.findOneAndDelete`.

الفرونت مبني على افتراض إن الـ API هتشتغل زي ما هي متوقّعة في الـ schemas والكنترولرز، فبمجرد ما تصلّح النقط دي هيشتغل كل حاجة (رفع الصور، عرض تفاصيل المنتج، التعليقات، حذف طلبات الحجز) من غير أي تعديل تاني في الفرونت.

## اللي اتعمل في الفرونت

- تسجيل حساب + تفعيل بالإيميل، تسجيل دخول بخطوتين (كود تحقق)، نسيت كلمة المرور.
- صفحة المتجر: بحث + فلترة بالسعر + تصفح صفحات.
- صفحة تفاصيل الأداة: معرض صور، تقييمات ونجوم، إضافة/تعديل/حذف تعليق.
- صفحة الحجز: بيانات العنوان ورقم التواصل، تأكيد الطلب، وإلغاؤه خلال ٣٠ دقيقة.
- الملف الشخصي: تعديل الاسم/كلمة المرور/الصورة، وحذف الحساب.
- لوحة تحكم (أدمن/مدير): إدارة الأدوات (إضافة/تعديل/حذف)، عرض طلبات الحجز (مع فلتر غير المدفوعة)، وعرض المستخدمين.
